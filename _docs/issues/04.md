# TT-04 — Team applications and roster approval

Status: Closed in GitHub after independent QA PASS and explicit user authorization; confirmed before 2026-10-13 13:29 UTC+5
GitHub issue: https://github.com/mjesenuly/tournament-tracker/issues/4
Product source: ../plan.md

## Goal

Register eligible teams through captain applications reviewed by the owner organizer.

## Acceptance criteria

- [ ] Captain submits name/contact, team name, 6–13 players with names, Student IDs, shirt numbers and positions.
- [ ] Applications require at least one goalkeeper and reject duplicate identities and invalid roster data.
- [ ] Owner organizer approves or rejects pending applications; captain cannot approve.
- [ ] Approval transaction enforces one Student ID per team across the entire tournament, including concurrent approvals.
- [ ] Public roster reveals permitted names/numbers/positions and omits private identifiers/contact.

## Out of scope

Faculty requirement and new teams after fixture generation.

## Constraints

Whole-tournament eligibility remains reserved after removal. Document ID normalization and permitted positions. Depends on 02–03.

## Handoff and verification

Engineer records actual implementation commit and executed checks. Independent QA records criterion evidence and PASS/FAIL; failures return to engineer. Orchestrator alone closes a real issue after QA PASS. No implementation or publication is claimed by this specification.
