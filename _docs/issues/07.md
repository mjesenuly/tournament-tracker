# TT-07 — Midseason replacement approval

Status: Pending
GitHub issue: https://github.com/mjesenuly/tournament-tracker/issues/7
Product source: ../plan.md

## Goal

Replace/remove players through a manually controlled second window while preserving history.

## Acceptance criteria

- [ ] Owner manually opens/closes second window only after documented midpoint threshold.
- [ ] Captain proposes removals and corresponding replacements without standalone additions or new teams.
- [ ] Owner approval is atomic and validates resulting 6–13 roster with at least one goalkeeper.
- [ ] Approval rejects any replacement identity affiliated with another team earlier in the tournament.
- [ ] Old membership and goal statistics remain; future match eligibility uses updated membership.
- [ ] Rejected/pending changes leave the active roster unchanged; unauthorized approvals fail.

## Out of scope

Team transfers, unrestricted additions and automatic opening.

## Constraints

Document midpoint as proposed finished matches >= ceil(total/2), rather than user-approved detail. Preserve match-time snapshots. Depends on 04–06.

## Handoff and verification

Engineer records actual implementation commit and executed checks. Independent QA records criterion evidence and PASS/FAIL; failures return to engineer. Orchestrator alone closes a real issue after QA PASS. No implementation or publication is claimed by this specification.
